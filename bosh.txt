# PART 6 — TELEGRAM MINI APP AUTHENTICATION

This is a critical security requirement.

Use the official Telegram Web Apps SDK.

Implement:
- Telegram WebApp.ready()
- Telegram WebApp.expand()
- Telegram theme parameters.
- Telegram BackButton.
- Telegram MainButton where appropriate.

Authentication:

1. Receive Telegram initData from the Mini App.
2. Send initData to the backend.
3. Validate the Telegram signature using the bot token on the backend.
4. Validate auth_date and reject expired authentication data.
5. Extract the authenticated Telegram user.
6. Match the Telegram ID with the registered profile.
7. Create a secure application session.
8. Return a short-lived access token and appropriate refresh/session mechanism.

Never trust:
- Frontend Telegram user IDs.
- Unsigned user information.
- User-supplied coin balances.
- User-supplied scores.

Never expose the Telegram bot token in frontend code.

Never expose the Supabase service-role key in frontend code.

Users who have not completed registration must be redirected to the appropriate registration flow.

Provide a development-only authentication mode for local testing. It must be disabled in production.

# PART 8 — DAILY IQ TEST ENGINE

This is one of the most important features.

## 8.1 Daily schedule

Every day at exactly:

09:00 AM — Asia/Tashkent timezone.

A new IQ test must become available.

A background scheduler must:
1. Find or create the daily IQ test.
2. Publish it.
3. Send Telegram notifications to registered users.
4. Record notification delivery attempts.
5. Prevent duplicate publication and notifications.

Users must receive a Telegram message in their selected language.

Uzbek:
"🧠 Yangi kunlik IQ testingiz tayyor! Bugungi 10 ta savolga javob bering va coinlar to'plang."

Russian:
"🧠 Ваш новый ежедневный IQ-тест готов!"

English:
"🧠 Your new Daily IQ Test is ready!"

Include a button:
"Start IQ Test"

Use Telegram's bot messaging system.

## 8.2 Test structure

Exactly 10 questions per daily test.

Question categories:
- Logical reasoning.
- Mathematical reasoning.
- Number sequences.
- Pattern recognition.
- Problem solving.
- Analytical thinking.

Each question has:
- Question text.
- Four answer options.
- One correct answer.
- Difficulty.
- Coin reward.
- Optional explanation.
- Optional image.

Difficulty and rewards:

| Difficulty | Coins |
|---|---:|
| Easy | 1 |
| Medium | 2 |
| Hard | 3 |

The administrator controls question difficulty and rewards.

## 8.3 User test experience

Create a premium testing interface.

Display:
- Test title.
- Date.
- Question progress.
- Current question.
- Four answer options.
- Navigation controls.
- Submission confirmation.

Display one question at a time.

Save answers automatically on the backend.

Allow users to return to previous questions before submission.

Prevent duplicate submissions.

Persist progress if the user closes and reopens Telegram.

## 8.4 IQ result release — IMPORTANT

Do not display correct answers or final scores immediately.

The result becomes available exactly 24 hours after the daily test publication time.

Example:

Monday 09:00 — Test published.

Monday 10:00 — User completes test.

Tuesday 09:00 — Result released.

The release time is based on the daily test publication timestamp, not the user's completion time.

Before release, show:

"Your result will be available tomorrow at 09:00."

After release, display:
- Total correct answers.
- Total incorrect answers.
- Score.
- Percentage.
- Coins earned.
- Correct answers.
- Explanations.
- Individual question results.

Award coins only once, when the result is released.

Use backend transactions to prevent duplicate rewards.

Users who do not complete the test must not receive rewards.

Create historical test records in the profile.

- Calculate the score on the backend.

- Release the result immediately.

- Correct answers.
- Incorrect answers.
- Percentage score.
- Total score.
- Time spent.
- Earned coins.
- Correct answer for every question.
- Explanations.

## 9.5 Daily attempt restriction

A user can complete only ONE university entrance test per calendar day.

Official timezone: Asia/Tashkent.

Implement this restriction on the backend and database.

Important:
- One attempt per user per Tashkent calendar day.
- Refreshing must not create another attempt.
- Direct API requests must not bypass the restriction.
- Concurrent requests must not create duplicate attempts.
- Store the daily attempt date.
- Reset eligibility automatically on the next Tashkent calendar day.

## 9.6 Rewards

- Correct answers.

- Admin-configured reward values.
